# Inversion runs, August 2026 — batch a (corrected input data)

Thermochron.jl time-temperature inversions of the combined zircon and apatite
(U-Th)/He dataset from crystalline basement of the Montreal River monocline
(`../mrm.csv`: 55 ZHe and 13 AHe analyses, 68 chronometers total). Runs
conducted by N. Swanson-Hysell, launched August 24, 2026.

**These are the first runs made with corrected input data.** Every earlier batch
(`../guenthner_runs_2026-03/`, `../swansonhysell_runs_2026-04/`,
`../swansonhysell_runs_2026-07a/`, `-07b/`, `-07c/`) was run on a version of
`mrm.csv` in which the `raw He age [Ma]` column was populated with
**alpha-ejection-corrected** dates rather than raw (uncorrected) dates. The error
dates to the original creation of that file and was found by W. Guenthner in
August 2026 while rebuilding the input from the data notebook. Because
Thermochron.jl applies its own alpha-ejection correction internally as part of
the forward model, supplying already-corrected dates double-counts the
correction and biases the input dates old — by a median factor of 1.35 for the
zircons (Ft 0.60–0.92) and 1.53 for the apatites (Ft 0.57–0.84). Results from
the earlier batches should not be interpreted.

`../mrm.csv` is now generated by an explicit cell at the end of
`../../code/MRM_UTh_He_data.ipynb`, which draws the `uncorrected_date` and
`uncorrected_1s` columns from `../../data/UTh_He_zircon_data.csv` and
`../../data/UTh_He_apatite_data.csv`. The chronometer count also rises from 67
to 68 relative to the July batches, reflecting the duplicate-grain resolution in
the same rebuild.

## Contents

- `tTinversion_mrm.jl` — the exact inversion script used for these runs
- `run_batch.sh` — the batch runner used to launch the nine chains
- `Project.toml`, `Manifest.toml` — pinned Julia environment (Thermochron.jl
  v0.16.13, Julia v1.12.5, and the exact version of every dependency), identical
  to batches 07a/b/c
- `<config>_seed<N>.log` — run logs, including the configuration/seed header,
  package versions, post-burn-in summary statistics, and runtime (progress-bar
  output stripped)
- `MRM_*_tT_density.png`, `MRM_*_tT_density.json` — the posterior path-density
  image of each chain exported from its `.jld2` posterior by
  `../export_tT_density.jl` (8-bit, 1200 × 1800, normalised exactly as in the
  `_tT.pdf` plot; ranges and chain statistics in the `.json`). These are the
  inputs to `../../code/make_inversion_figures.py`, which assembles the
  composite manuscript figures in `../../figures/`
- `MRM_<config>_seed<N>_*` — posterior t-T path density maps (`_tT.pdf`),
  observed versus predicted date-eU plots for each mineral (`_Age-eU.pdf`),
  kinetic parameter posteriors (`_kinetics.pdf`), and MCMC diagnostic traces of
  log-likelihood, acceptance rate, and t-T node count (`_lldist.png`,
  `_acceptance.png`, `_ndist.png`)

The diagnostic traces are archived as 150 dpi rasterizations because the vector
originals plot all 10⁶ steps and run to ~15 MB each. The full posterior
distributions (`.jld2`, ~800 MB each) are not archived, as each chain can be
regenerated exactly from its seed and the pinned environment.

## Design

Three constraint configurations at the three seeds used in the July 2026
batches, so that these chains differ from their July counterparts **only in the
input data**. Holding the seed fixed separates the effect of the corrected dates
from the chain-to-chain variability documented in
`../swansonhysell_runs_2026-07b/README.md`.

| Configuration | Constraints applied |
| --- | --- |
| `unconstrained` | none |
| `no_jacobsville` | Midcontinent Rift burial (250–400 °C, 1050–1100 Ma); Cambrian near-surface (20–50 °C, 485–505 Ma) |
| `all_constraints` | the above, plus Jacobsville near-surface (20–50 °C, 980–1000 Ma) |

## Reproducing these runs

From the `inversion_files/` directory:

```
julia --project=swansonhysell_runs_2026-08a tTinversion_mrm.jl <config> <seed> swansonhysell_runs_2026-08a
```

for each of `<config>` ∈ {`unconstrained`, `no_jacobsville`, `all_constraints`}
and `<seed>` ∈ {20260710, 12345, 777}, or all nine via
`bash swansonhysell_runs_2026-08a/run_batch.sh`. Each run takes roughly 20 hours;
the runner holds five chains in flight at a time.

## Configuration

All runs used 1,000,000 MCMC steps (500,000 burn-in), an 8 Ma timestep over a
2704 Ma model span, 15 to 50 t-T nodes, and the `MCMC_varkinetics` routine, in
which RDAAM (apatite) and ZRDAAM (zircon) damage-diffusivity parameters are
resampled during the inversion. Geological constraints are applied as uniform
(box) priors. This is unchanged from batches 07a/b/c.

### The seed-dependence documented in July does not survive the data correction

The July batches were run on the double-corrected input file. Their
likelihoods, for comparison:

| Configuration | 20260710 | 12345 | 777 | spread |
| --- | --- | --- | --- | --- |
| `unconstrained` (July) | -492.3 | -492.9 | -492.6 | 0.6 |
| `no_jacobsville` (July) | -481.5 | -471.3 | -470.0 | 11.5 |
| `all_constraints` (July) | -483.6 | -482.7 | — | 0.9 |
| `unconstrained` (August) | -446.4 | -446.4 | -446.0 | 0.4 |
| `no_jacobsville` (August) | -446.0 | -445.7 | -445.8 | 0.3 |
| `all_constraints` (August) | -448.9 | -449.8 | -449.3 | 0.9 |

Two features of the August runs bear on the convergence problem described at
length in `../swansonhysell_runs_2026-07b/README.md`.

First, the `no_jacobsville` configuration, whose three July chains spanned 11.5
log-likelihood units and placed visibly different amounts of Neoproterozoic
path density, now reproduces across the same three seeds to within 0.3 units.

Second, and more diagnostically, the ordering of the configurations is now the
expected one. Geological constraints enter as priors that restrict the
accessible t-T space, so a constrained chain cannot fit the data better than a
well-mixed unconstrained chain. In July the `no_jacobsville` chains reported
likelihoods 11 to 22 units *higher* than the unconstrained chains, which is the
signature of an unconstrained chain that has failed to locate the
high-likelihood region rather than of a genuinely better fit. In August
`unconstrained` and `no_jacobsville` are indistinguishable (-446.0 versus
-446.0 at the shared seed) and `all_constraints` sits about 3 units below them,
which is the modest and interpretable cost of requiring near-surface conditions
at the time of Jacobsville deposition.

Taken together these are consistent with the July convergence pathology having
been substantially an artifact of the input data rather than a property of this
inversion problem. Supplying alpha-ejection-corrected dates to a forward model
that applies its own ejection correction asks the sampler to fit dates that are
too old by a grain-size-dependent factor, and the resulting likelihood surface
was evidently harder to sample. The absolute log-likelihoods are not comparable
between July and August because the data being fit differ; the spread across
seeds and the ordering of configurations within each batch are.

W. Guenthner's July assessment that the large unconstrained prior volume would
require chains of order 10^7 iterations to converge is not contradicted by
these runs, but at 10^6 steps three independent seeds now agree to a few tenths
of a log-likelihood unit in every configuration, so chain length does not
appear to be the limiting factor for the features carried in the manuscript.

### Sensitivity still outstanding

Two zircon analyses, `TAI_MRM4_z3` and `TAI_MRM4_z5`, lie far above the Archean
basement date-eU array and contain anomalously high helium concentrations for
their eU. They are retained in these runs. Their influence is tested in
`../swansonhysell_runs_2026-08b/`, which repeats a configuration from this
batch with the two grains removed.
